# Autonomous investigation execution — Phase 4.2

This document describes the internal Phase 4.2 execution interface. Phase 4.3
integrates it with authenticated API controls, backend incident notifications and
the existing Investigation page; see [DASHBOARD.md](DASHBOARD.md). The execution
interface itself never performs live recovery.

```python
import asyncio
from app.investigation_agent import (
    capture_investigation_inputs, run_autonomous_investigation, PlanningBudget,
)

# Explicitly invoked by a trusted caller. Existing runtime lock protects the
# read-only evidence projection and the existing detached snapshot capture.
context, reference = await capture_investigation_inputs(runtime, incident_id)
report = await asyncio.to_thread(
    run_autonomous_investigation, context, reference,
    PlanningBudget(max_candidates=3, max_experiments=3, duration_ticks=20),
)
```

`SnapshotReference` binds a detached snapshot to caller-provided run/reference
identifiers. Prefer the atomic capture helper. A bare snapshot has no run identity
and is rejected. Manually bound references require trusted caller provenance;
matching arbitrary strings is not proof of provenance. Run/tick mismatches are
rejected, and the actual captured horizon and existing work limits are enforced.
No snapshot is ever passed to the planner or fusion function. The execution layer
reads only run/tick/reference/horizon metadata and passes the opaque snapshot to
the existing ShadowTwin execution and assessment functions. It never examines
hidden schedules to choose a test. No simulator or database object enters a report.

## Workflow and adaptation

1. Invoke the unchanged Step 4.1 selection policy with one requested next test.
2. Run that mechanism once via the existing `run_experiment`; both branches fork
   from the same original snapshot, not the previous intervention's ending state.
3. Assess cached actual results through the new `assess_experiments` entry point
   in the existing comparison module. It shares the original residual, conservation,
   comparability and Pareto logic with `compare_hypotheses`. Nothing is simulated
   again for ranking. One result has outcomes but no multi-hypothesis rank.
4. Retain original dated investigation targets that remain unresolved in the
   virtual result. Existing comparison residuals determine remaining targets;
   original security-log targets are removed only when actual experimental rows
   explicitly show those flags are no longer abnormal throughout the window.
5. Ask the original planner for a different justified mechanism. A failed or invalid
   result retains the original targets and may justify a supported alternative.
   Already attempted mechanisms are excluded. There are no retries.

Follow-up context is a **subset of original observations**, not new live evidence.
Experimental samples are never backdated to the original tick. New abnormalities
introduced only in a virtual future are reported as limitations/contradictions,
not silently promoted to live measurements or new historical sources. A later
integration can explicitly obtain fresh observable context when appropriate.

Real adaptive regression: two simulations have identical observations through tick
9, but the solar disturbance ends at tick 10 in one and persists in the other.
Controller restoration is the first selected test in both. If no solar abnormality
remains in that virtual window, the agent stops; otherwise the planner selects the
solar pathway next. The orchestrator does not inspect the differing schedules.

## Evidence fusion and report

The JSON report separates original model records, original observable evidence,
actual experimental findings, contradictions, limitations and remaining hypotheses.
An approved immutable `ModelRecord` projection was added to `ObservableContext`
for reporting original anomaly/source/Stage B values and candidate scores. It does
not change planner priorities. Historical/undated model records retain their scope.
Missing model output stays unavailable; no predictions are generated by the agent.

Duplicate signal/tick/value/threshold/unit records are grouped with their separate
provenance/evidence IDs. Correlated logs, residuals and classifier views are not
counted as independent confirmation. No scores are averaged or converted into a
new confidence. Original reported model scores remain only original model scores.

`steps` include selection reasons, original evidence, actual starting/ending ticks,
execution status, paired observable telemetry, actual measurement differences,
existing physical residual changes, delivered-energy differences and the next-action
decision. The final shared assessment determines comparability and ranking.
Raw simulator records are not serialized: paired telemetry is passed through the
existing `ComparisonFrame` observable projection. Unknown metadata is excluded.

`final_assessment.most_useful_tested_intervention` is populated only when the
existing multi-result comparison reports distinguishable ranked prospective evidence.
One tested intervention cannot manufacture a ranking. Source assessment remains
Inconclusive: these tests cannot independently distinguish the retained malfunction
and manipulation explanations or establish historical malicious intent. Negative
energy and worsened measurements are preserved as mixed/adverse findings.

## Bounds and stopping

Defaults: 3 distinct admitted mechanisms, at most 3 attempts, 20 ticks per branch,
and at most the existing 480 branch-tick limit. `PlanningBudget` is reused without
increasing its limits. Each attempt reserves `2 * duration_ticks`, including failed
or unsupported attempts; `branch_ticks_charged` is conservative budget accounting,
not a claim that a failed attempt actually advanced every reserved tick.

Stopping reasons distinguish:

- Non-ready planner states: insufficient evidence, no relevant current abnormality,
  unsupported mechanisms or budget exhaustion.
- No measurable comparison abnormality in the current prospective window.
- Sufficient intervention evidence with no justified additional target.
- No additional distinguishing supported experiment.
- Work, experiment-count, candidate-admission or captured-horizon exhaustion.
- Failed, unsupported, invalid or incomparable experiments without useful alternatives.
- A repeated-mechanism request prevented without execution.

Invalid run/tick identity is an explicit validation error. Invalid results remain
charged attempts, with no invented measurements. If some results are invalid and
others valid, the report is partial. Comparisons with incompatible controls or
random-stream/external-condition divergence do not acquire an artificial ranking.

No live operated/baseline/uncorrected branch, schedule, ledger, incident, or database
is changed. No fault/attack is injected by the agent. All effects are within the
existing detached experimental forks. Reports stay in memory; no tables are added.
The caller must separately recheck live run identity before presenting results if
live simulation/reset occurred after capture. No historical replay is implemented.

Step 4.3 UI integration, automatic triggers, external AI, new classifiers, training,
new physics, live recovery, Proof Mode and cloud services are not implemented.
